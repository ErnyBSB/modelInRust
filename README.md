# IBM Model 1 in Rust: Didactic Implementation Project

This project is a small, educational Rust implementation of **IBM Model 1**, one of the foundational probabilistic models in statistical machine translation.

The goal is not to build a complete translation system. The goal is to demonstrate how a simple probabilistic translation model can learn word-to-word translation probabilities from a small parallel corpus using the **Expectation-Maximization (EM)** algorithm.

## 1. Educational goal

The implementation demonstrates the following pipeline:

```text
parallel corpus -> vocabularies -> translation table t(f | e) -> EM training -> word alignments
```

Where:

- `e` is a source-language word, in this project represented by English tokens;
- `f` is a target-language word, in this project represented by French tokens;
- `t(f | e)` is the probability that source word `e` generates target word `f`;
- `<NULL>` represents the empty source token, also called the empty cept in the IBM Model 1 literature.

## 2. What this project implements

The project implements the complete didactic version of IBM Model 1:

1. Read parallel sentence pairs from a TSV file.
2. Tokenize source and target sentences.
3. Build source and target vocabularies.
4. Add the special `<NULL>` token to every source sentence.
5. Initialize translation probabilities `t(f | e)` uniformly from sentence-level co-occurrences.
6. Run EM training:
   - E-step: compute expected counts for possible alignments;
   - M-step: normalize expected counts and update `t(f | e)`.
7. Print learned translation probabilities.
8. Produce a simple Viterbi-style alignment by selecting the source word with the highest `t(f | e)` for each target word.

## 4. Input data format

The corpus file must be a UTF-8 TSV file with two columns:

```text
source_sentence<TAB>target_sentence
```

Example:

```text
the house	la maison
the book	le livre
a house	une maison
```

The sample corpus is available at:

```text
data/toy.tsv
```

From the project root:

## 6. Core IBM Model 1 idea

IBM Model 1 assumes that each target word can be generated by any source word in the sentence, including the special `<NULL>` token. It ignores word order, which makes it mathematically simple and computationally efficient.

For each target word `f_j`, the model computes the responsibility of each source word `e_i` as:

```text
delta(e_i, f_j) = t(f_j | e_i) / sum_i t(f_j | e_i)
```

This value is used as a fractional count. After accumulating these counts across the whole corpus, the model updates the probabilities:

```text
t(f | e) = count(e, f) / total(e)
```

This is the practical EM update used in the code.

## 7. Main design choices

### 7.1 Token IDs instead of strings

Words are converted to integer IDs:

```rust
type TokenId = usize;
```

This makes indexing easier and keeps the model closer to real NLP implementations.

### 7.2 Sparse translation table

The translation table is stored as:

```rust
HashMap<TokenId, HashMap<TokenId, f64>>
```

Conceptually, this means:

```text
table[e][f] = t(f | e)
```

This is less memory-intensive than a dense matrix and clearer for didactic purposes.

### 7.3 Explicit `<NULL>` token

Each source sentence receives the special `<NULL>` token at position 0:

```text
<NULL> the house
```

This allows target words to be generated without a direct source-language counterpart.

### 7.4 Small corpus first

The project is intentionally designed for small corpora. This keeps the EM process easy to inspect and explain.

## 8. Suggested teaching sequence

A good classroom sequence is:

1. Run the program with the toy corpus.
2. Show the initial uniform probabilities conceptually.
3. Explain the E-step as fractional alignment counting.
4. Explain the M-step as probability normalization.
5. Run 1, 5, and 10 iterations and compare the results.
6. Inspect the learned probabilities.
7. Inspect the final alignments.
8. Discuss why IBM Model 1 ignores word order and why later IBM Models add more structure.

## 9. What this project intentionally does not implement

To keep the implementation didactic, the following features are intentionally omitted:

- IBM Models 2 to 5;
- a full translation decoder;
- advanced smoothing;
- large-scale corpus processing;
- parallel training;
- log-space numerical optimization;
- neural networks;
- embeddings;
- Transformer-based translation.

## 10. Suggested extensions

Possible next steps:

1. Save the trained translation table to JSON or CSV.
2. Add unit tests for normalization: `sum_f t(f | e) = 1`.
3. Add support for larger corpora.
4. Add optional alignment output in Pharaoh format.
5. Add parallel expected-count computation with Rayon.
6. Implement IBM Model 2 to introduce positional alignment probabilities.
7. Compare the learned lexical table with modern embedding-based similarity.

## 11. Conceptual summary

IBM Model 1 is a probabilistic, trainable model. It is not a neural model and not a modern LLM. Its learned parameters are simply a table of translation probabilities `t(f | e)`. Still, it is a machine learning model in the classical statistical sense because it estimates parameters from data.

This Rust project makes that process explicit and inspectable.
